#### 资源目录

`res/`  

+ `layout/`：存放 XML 布局文件。`inflate()` + `R.layout.xxx`。
+ `drawable/`：`getDrawable()` + `R.drawable.xxx`。
  + Bitmap（位图）：PNG、JPG 等。（它们本质上是由像素点阵组成，其实就是一个二维像素数组，区别于矢量图。这些图片加载到内存后都会变成 Bitmap 对象）
  + XML Drawable：用 XML 描述的 Drawable 子类。包括矢量图、形状、状态列表等。它们不是图片文件，而是通过代码绘制，不存在分辨率适配问题。
+ `raw/`：存放原始资源文件，不会对其进行任何编译处理，原封不动打包进 APK。`openRawResource()` + `R.raw.xxx`。
  + 比如 mp3、JSON 等数据。
  + 会放 mp4 吗？一般不会，放不放核心考虑的点是体积大不大，视频体积通常比较大，会导致 apk 的大小变大。像图片，即使区分不同屏幕密度，最终也不回占用多少空间；而 mp4，即使不区分，单单一个，也会占用较大空间。正常来说，视频都会存储在云端。
  + 上面所说的“不会对其进行任何编译处理”是指，比如对于 mp3，在最终生成的 APK 中，字节流还是一致的（MD5不变）。而放在 `drawable/` 里的 png，AAPT2 会进一步进行压缩，比如移除元数据等，从而改变字节流。
+ `values/`：放简单值资源，也就是是定义可复用的常量。其实你完全可以起任意文件名字，甚至把这些都放在一个文件里，只要放在根目录 `<resources>` 里即可。
  + `strings.xml`：字符串。`R.string.xxx`，`<string name="xxx">`。
  + `colors.xm`：颜色值。`R.color.xxx`，`<color name="xxx">`。
  + `dimens.xml`：尺寸（dp/sp）。`R.dimen.xxx`，`<dimen name="xxx">`。
  + `themes.xml / styles.xml`：主题和样式。`R.style.xxx`、`<style name="xxx">`。
  + `arrays.xml`：数组（字符串数组、整数数组）。`R.array.xxx`，`<string-array name="xxx">`、`<integer-array name="xxx">`、`<array name="xxx">`。
  + `attrs.xml`：自定义属性声明。`R.styleable.xxx`，`<declare-styleable name="xxx">`。
  + `bools.xml`：布尔值。`R.bool.xxx`，`<bool name="xxx">`。
  + `integers.xml`：整数值。`R.integer.xxx`，`<integer name="xxx">`。
+ `mipmap/`：专门用于存放应用图标。Settings 是系统预装应用，不是普通 App，启动图标可能由系统 ROM 统一管理，不在 App 自己的工程里定义。为什么专门搞个文件夹来存放应用图标？Android 打包时会按屏幕密度进行瘦身，也就是比如 `drawable-xhdpi/` 里的资源在 hdpi 设备上会被裁掉。但对于应用图标，不同区域所展示的图标可能是不同的，会访问不同密度的图标。`R.mipmap.xxx`。
+ `xml/`（不常用）：某个特殊功能可能会用到的配置文件，比如 `<appwidget-provider>`，里面会定义桌面小组件的大小。
+ `font/` （不常用）：存放字体，ttf，用来不跟随系统。
+ `menu/`（不常用）：专门给 Toolbar、BottomNav、PopupMenu 用的，里面的一个 item 包含了标题和 icon。
+ `anim/` 或 `animator/`（不常用）：前者存放补间动画，后者属性动画。但更多时候都是用代码控制，可以支持动态计算值，调试也更容易。

#### 资源限定符

在 `res/` 中创建以 `<resources_name>-<qualifier>` 形式命名的新目录。

- `<resources_name>`：默认目录的名称。
- `<qualifier>`：限定符，对应一种配置条件。

例子：

```9
res/
├── layout/              ← 默认布局
├── layout-land/         ← 横屏时的替代布局
├── drawable-xhdpi/      ← xhdpi屏幕密度下的图片
├── drawable-zh-rCN-sw600dp-night-xxhdpi-v31 ← 中文、最小宽度≥600dp、深色模式、xxhdpi密度、Android 12+时的图片
├── values-zh/           ← 中文环境下的字符串
└── values-night/        ← 深色模式下的字符串
```

Android 会通过将设备配置信息与资源目录名称中的限定符进行比较，选择最符合当前设备的各个资源版本。如果使用多个限定符，则必须按照下面表中所列顺序添加到目录名称后。为了确保发生匹配不到的问题，一定要有默认的，也就是没有限定符的目录名称。

| 限定符         | 示例                                                         |
| :------------- | :----------------------------------------------------------- |
| 语言/区域      | `values-zh/`、`values-en-rUS/`、`values-fr-rFR/`             |
| 夜间模式       | `values-night/`、`drawable-notnight/`（默认就是 notnight）   |
| 屏幕密度 (dpi) | `drawable-anydpi/`（表示适合于任何密度；优先级最高）、`drawable-mdpi/`（默认）、`drawable-hdpi/`、`drawable-xhdpi/`、`drawable-xxhdpi/`、`drawable-xxxhdpi/`、`drawable-nodpi/`（多少 px 就是多少，禁止任何缩放；优先级最低，当然大于没有限定符的） |
| 屏幕尺寸       | `layout-sw600dp/`（最小宽度 ≥ 600dp，如平板）                |
| 平台版本       | `values-v26/`、`drawable-v21/`                               |

它的匹配原则是这样的

+ 与设备配置矛盾的目录直接去掉（密度和屏幕尺寸除外）。
+ 密度全保留，最终选最接近设备密度的那个。
+ 屏幕尺寸，小可以给大用，大不能给小用。
+ 根据优先级，匹配高优先级的。
+ 当匹配的限定符目录中找不到资源时，会回退到无限定符的默认目录，不会去其他限定符目录中查找

#### assets/

它是和 `res/` 同级的：

```
app/src/main/
├── java/
├── res/
├── assets/
└── AndroidManifest.xml
```

和 `res/` 的区别：

| 特性           | assets/                                                      | res/raw/                                                     |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **资源 ID**    | 不生成 R.raw.xxx，无法通过 ID 直接引用。                     | 编译后会生成 R.raw.xxx，可通过 ID 引用。                     |
| **访问方式**   | 通过 AssetManager 和路径字符串，`AssetManager.open("path/file.txt")`返回 InputStream。 | 通过资源 ID，`Resources.openRawResource(R.raw.file)` 返回 InputStream。 |
| **文件夹结构** | 支持任意层级子目录。                                         | 不支持子目录。                                               |
| **文件名限制** | 宽松，支持更多字符。                                         | 严格，只能用小写字母、数字、下划线，不能以数字开头。         |
| **配置限定符** | 不支持。                                                     | 支持。                                                       |

放在 `res/` 或 `assets/` 里的文件，都是不会进行任何编译处理的，仅仅会“无损压缩”（如果存放的是已经是压缩格式的文件，如 .zip, .gz，或者某些特定的多媒体文件，AAPT2 通常不会再次压缩），但内容是不变的，即 MD5 不会改变。

#### 屏幕密度

屏幕密度（Screen Density）是指屏幕单位物理面积内包含的像素数量，用 DPI（Dots Per Inch，每英寸点数）来表示。

- 分辨率（Resolution）：屏幕上一共有多少个像素点（比如 1080 x 1920）。
- 物理尺寸（Physical Size）：屏幕的实际大小（比如 5 英寸、10 英寸）。
- 屏幕密度（DPI）：分辨率 / 物理尺寸。

如果没有密度这个概念，我们直接用像素（px）开发 UI，比如要画一个 100 * 100 像素的按钮，在老手机上（密度低，像素点大），这 100 个像素点可能占用了 1 厘米的宽度，用户点起来很舒服；在新手机上（密度极高，像素点像针尖一样小），同样的 100 个像素点，物理宽度可能只有 2 毫米，用户根本点不到。

Android 规定，在 160 DPI 的屏幕上，1dp 物理上就等于 1px。当你使用 100dp 时，系统会根据当前手机的密度，自动计算它该显示多少像素。

| 级别                       | 缩写    | DPI 范围 | 换算比例（以 mdpi 为 1） | 对应的分辨率示例        |
| -------------------------- | ------- | -------- | ------------------------ | ----------------------- |
| **Medium**                 | mdpi    | 160 dpi  | 1                        | 320x480（老古董）       |
| **High**                   | hdpi    | 240 dpi  | 1.5                      | 480x800                 |
| **Extra High**             | xhdpi   | 320 dpi  | 2                        | 720x1280（720p）        |
| **Extra Extra High**       | xxhdpi  | 480 dpi  | 3                        | 1080x1920（1080p 主流） |
| **Extra Extra Extra High** | xxxhdpi | 640 dpi  | 4                        | 1440x2560 （2K/4K 屏）  |

```java
public String loadJSONFromAsset(Context context, String fileName) {
    String json = null;
    try {
        // 获取 AssetManager
        AssetManager manager = context.getAssets();
        // 打开文件输入流
        InputStream is = manager.open(fileName);
        
        int size = is.available();
        byte[] buffer = new byte[size];
        is.read(buffer);
        is.close();
        
        json = new String(buffer, "UTF-8");
    } catch (IOException ex) {
        ex.printStackTrace();
        return null;
    }
    return json;
}
```







#### AAPT2

https://www.jianshu.com/p/ea6c09c74b0e

https://www.jianshu.com/p/8d691b6bf8b4

编译应用时，`aapt` 会生成 `R` 类，其中包含 `res/` 目录中所有资源的资源 ID。每种类型的资源都有对应的 `R` 子类（例如，`R.drawable` 对应所有可绘制资源）。且相应类型的每个资源都有对应的静态整数（例如 `R.drawable.icon`）。该整型数就是可用来检索资源的资源 ID。



无论是 assets/ 还是 res/raw/，AAPT 默认会对大多数文件进行压缩以减小 APK 体积。但它有一个**内置的名单**，对于那些已经是压缩格式的文件（再压缩也减不了多少空间，反而浪费 CPU），它会选择 **STORED（不压缩）** 存储。

常见的**不压缩**扩展名包括：

- **视频/音频**：.jpg, .png, .gif, .wav, .mp3, .ogg, .mp4, .m4a
- **压缩包**：.zip, .gz, .rar, .7z
- **其他**：.pdf 等。

**如果你的文件后缀不在这个名单里**（比如 .txt, .json, .xml, .dat），无论放在 assets/ 还是 res/raw/，默认都会被 **DEFLATE（压缩）**。





```groovy
android {
    // ...
    aaptOptions {
        // 指定某些后缀不进行压缩
        noCompress 'tflite', 'db', 'bundle'
    }
}
```
