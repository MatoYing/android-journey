#### 为什么使用 Log 而不使用 `System.out.println`

+ `android.util.Log` 是针对 Android 平台设计的，底层由系统处理，可根据等级过滤，还可以写入缓冲；`System.out.println` 始终直接输出，无等级区分、无缓存优化。
+ 配合 Logcat，可以方便的按 TAG、等级、进程过滤。

#### Intent 能干些啥

Intent 本质是描述“我要做什么”的消息对象，描述行为 + 附带数据，系统或组件根据 Intent 信息去做路由，找到对应组件执行相应动作。

常见用途，比如：

+ 启动 Activity

  ```java
  Intent intent = new Intent(context, DetailActivity.class);
  intent.putExtra("id", 123);
  startActivity(intent);
  ```

+ 启动 Service

  ```java
  Intent intent = new Intent(context, SyncService.class);
  context.startService(intent);
  ```

+ 发送广播

  ```java
  Intent intent = new Intent("ACTION_USER_LOGIN");
  sendBroadcast(intent);
  ```

常见参数：

```java
// 组件
intent.setClass(context, TargetActivity.class);
// 动作（自己实现，或者使用内置动作）
intent.setAction(Intent.ACTION_VIEW);
// 类别（隐式Intent必须有动作和类别）
intent.addCategory(Intent.CATEGORY_LAUNCHER);
// 数据
intent.setData(Uri.parse("https://www.google.com"));
// 附加参数
intent.putExtra("key1", 123);
// 任务栈启动方式
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
```

#### Android 签名机制

> https://blog.csdn.net/qian1127/article/details/103531761

**1）为什么要签名？**

+ 应用身份与升级校验：Android 通过对比包名（Package Name）和签名（Signature）来判断是否是同一个应用。只有签名一致，才能覆盖安装（升级）。防止恶意应用冒充正版应用。
+ 应用完整性校验：每个 APK 都必须使用开发者私钥签名，系统安装时会用公钥验证。如果 APK 内容被修改（如插入广告、病毒、后门），签名验证就会失败。这样可以保证应用在分发过程中未被篡改，防止“被二次打包”。
+ 模块化部署与进程复用：Android 默认每个应用运行在独立的 UID（用户空间）中，互相隔离。若两个应用使用相同签名，可以声明相同的 SharedUserId，系统会允许它们运行在同一进程，可以共享私有数据目录，可以直接访问彼此的组件和数据。从而实现模块化设计，如一个主 App + 多个功能插件。
+ 使用第三方服务：许多第三方 SDK（如微信、支付宝）会检查调用 App 的签名是否匹配注册签名，如果签名不匹配，将拒绝授权调用。防止伪造应用冒用合法 App 身份。

**2）签名机制的演进**

+ V1 签名（传统版）：对 APK（本质是一个 ZIP 包）中的每一个文件进行 Hash 计算，然后用私钥加密。安装时，系统会解压 APK，逐个校验文件签名是否匹配。缺点的话就是速度慢，因为要校验所有文件；还有就是它没有保护其中的元数据（每个文件的文件名、大小、压缩方式、文件顺序等等），不安全。
+ V2 签名（全包版 - Android 7.0+）：将整个 APK 文件看作一个二进制数据块进行校验。优点是速度快，更安全，任何对 APK 的字节级修改都会导致签名失效。
+ V3 签名（换钥版 - Android 9.0+）：在 V3 之前，如果开发者的私钥丢失或泄露，或者想换更强的加密算法，就必须更换签名。但更换签名意味着无法覆盖安装旧版本，用户必须卸载重装，导致数据丢失，V3 在签名块中添加了 Proof-of-rotation（轮替证明）结构。它包含了一个链表，记录了从旧密钥到新密钥的信任链。允许 APK 在更新时更改签名密钥。只要新密钥能证明它是由旧密钥授权的（或者属于同一个信任链），系统就允许升级。
+ V4 签名（流式版 - Android 11+）：支持增量安装，安装时按“块”下载 APK；每个块都有对应的校验信息，系统只验证你当前用到的那些块，不用等整包。配合 Google Play 实“边下边玩”。当然 V4 必须配合 V2 或 V3 一起使用。

2）随时随地退出程序

```java
public class ActivityCollector {
    // 静态List，用于暂存所有正在运行的Activity
    public static List<Activity> activities = new ArrayList<>();

    // 添加活动：在BaseActivity的onCreate中调用
    public static void addActivity(Activity activity) {
        activities.add(activity);
    }

    // 移除活动：在BaseActivity的onDestroy中调用
    public static void removeActivity(Activity activity) {
        activities.remove(activity);
    }

    // 一键结束所有活动
    public static void finishAll() {
        for (Activity activity : activities) {
            // 只有当Activity还没销毁时才调用finish
            if (!activity.isFinishing()) {
                activity.finish();
            }
        }
    }
}

public class BaseActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        // 活动启动时，自动加入集合
        ActivityCollector.addActivity(this);
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        // 活动销毁时，自动移出集合，防止内存泄漏
        ActivityCollector.removeActivity(this);
    }
}

// 在任何地方（比如“退出登录”按钮的监听器里）直接调用
ActivityCollector.finishAll();
```

3）启动活动的最佳写法

解决团队协作时，不知道启动目标 Activity 需要传递哪些参数（Intent Extras）的问题

```java
Intent intent = new Intent(FirstActivity.this, SecondActivity.class);
intent.putExtra("param1", "data1"); // 你怎么知道SecondActivity需要"param1"
intent.putExtra("param2", "data2"); // 如果少传了参数，程序可能会崩
startActivity(intent);

// 替换版
SecondActivity.actionStart(FirstActivity.this, "hello", "world");
```

```java
public class SecondActivity extends BaseActivity {

    // 将需要的参数直接定义为方法参数
    public static void actionStart(Context context, String data1, String data2) {
        Intent intent = new Intent(context, SecondActivity.class);
        // 内部处理PutExtra，外部不需要关心key是什么
        intent.putExtra("param1", data1);
        intent.putExtra("param2", data2);
        context.startActivity(intent);
    }
    
    // ...
}
```
