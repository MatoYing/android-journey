### 异常体系

![image-20260831192352579](../assets/image-20260831192352579.png)

Throwable 是 Java 异常体系的根类（继承于 Object)，所有可被抛出的对象都必须继承它。它有两个直接子类：Error 和 Exception。

+ Error：表示 JVM 层面的严重错误，程序无法恢复。不需要也不应该捕获。像是内存溢出、栈溢出、类加载失败。
- Exception：程序本身可以处理的异常，可以通过 catch 捕获。
    - Checked Exception：受检异常。编译期强制检查，必须用 try-catch 捕获或用 throws 声明。表示"程序逻辑本身没错，但外部条件可能导致失败"。像是文件不存在、网络不通、数据库连接失败。
    - Unchecked Exception（**RuntimeException**）：运行时异常。编译期不强制处理，运行时才抛出。表示"代码本身有 bug"，应该修复代码而不是捕获。像是空指针、数组越界、类型转换错误。
##### Throwable 为什么要分两类呢？
Error 代表了严重错误，通常是由 JVM层面或底层资源导致的。一旦发生 Error，程序不应该试图去捕获它，尽管技术上可以 catch，但这是极坏的实践。比如内存溢出时，catch 里做任何操作都可能需要内存，陷入死循环；栈溢出时，执行 catch 本身也需要栈空间，可能直接无法执行。总之 Error 发生时，JVM 内部状态已经不可靠，继续运行可能产生不可预期的行为。
Exception 代表程序可以预见并处理的异常情况，分为两类：外部环境导致的（如文件不存在、网络中断），程序逻辑 bug 导致的（如空指针、数组越界）。前者可以通过重试、降级等方式恢复，后者应该修复代码而非捕获。
所以主要的点，是发生后能不能“**恢复**”的问题。
##### Exception 为什么要分两类呢？
核心初衷是为了在代码的健壮性与开发效率之间取得平衡。 Checked Exception 表示"程序逻辑本身没错，但外部条件可能导致失败"，设计者认为这些问题是无法避免的，一定可能会发生的，调用者就必须有应对方案（要么捕获处理，要么声明抛出让上层处理），从而保证程序的稳健性。
Unchecked Exception 表示"代码本身有 bug"，这些错误本该通过改进代码逻辑来避免解决的。如果把它们也设为受检异常，代码中将到处充斥着 try-catch 或 throws 声明，极大地增加重复冗长的代码。
所以主要的点，是能不能“**避免**”的问题。在实现自定义异常时，到底继承 RuntimeException 还是 Exception 可以考虑这个点。
### Throwable 类常用方法有哪些？
- `String getMessage()`：仅返回异常的描述信息。
- `String toString()`：返回异常的类名和简短描述信息。
- `void printStackTrace()`：打印完整的异常堆栈信息（第一选择）。
```java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    e.getMessage();  // "/ by zero"
    e.toString();  // "java.lang.ArithmeticException: / by zero"
    e.printStackTrace();
    // java.lang.ArithmeticException: / by zero
    //   at com.example.Main.main(Main.java:3)
}
```
### 常见异常
```
Throwable
├── Error
│   ├── VirtualMachineError（JVM虚拟机运行出了问题）
│   │   ├── OutOfMemoryError           ← 堆/元空间/直接内存耗尽
│   │   └── StackOverflowError         ← 线程栈溢出
│   └── LinkageError（编译通过了，但运行时类的结构对不上）
│       ├── NoClassDefFoundError       ← 编译时这个类存在，运行时ClassLoader找不到它了
│       ├── NoSuchMethodError          ← 类找到了，但类里没有编译时期望的那个方法
│       ├── NoSuchFieldError           ← 类找到了，但类里没有编译时期望的那个字段
│       ├── IncompatibleClassChangeError（接口定义了方法，但运行时的实现类还没实现这个新方法）
│       │   └── AbstractMethodError    ← 接口定义了方法，但运行时的实现类还没实现这个新方法
│       └── ExceptionInInitializerError ← 类的static{}代码块或static成员变量初始化时抛了异常
│
└── Exception
    │
    ├── RuntimeException
    │   ├── NullPointerException       ← 对null进行解引用（调用方法、读取属性、拆箱等）
    │   ├── IllegalArgumentException   ← 传递了不合法的参数
    │   │   └── NumberFormatException  ← 字符串转换数值失败（如Integer.parseInt("abc")）
    │   ├── IllegalStateException      ← 对象当前状态不满足执行该操作的条件
    │   ├── IndexOutOfBoundsException  ← 索引越界
    │   │   ├── ArrayIndexOutOfBoundsException  ← 数组下标越界
    │   │   └── StringIndexOutOfBoundsException ← 字符串charAt/substring越界
    │   └── ClassCastException         ← 类型强转失败
    │
    └── Checked Exception
        ├── IOException（I/O与网络操作异常）
        │   ├── FileNotFoundException  ← 文件不存在或没权限
        │   └── SocketException（网络套接字出问题）
        │       ├── SocketTimeoutException ← 连接或读取超时
        │       └── ConnectException   ← 对方服务没启动，连不上
        ├── SQLException               ← 数据库操作失败（语法错、连接断、锁超时）
        ├── InterruptedException       ← sleep/wait/join时被叫醒（线程被中断）
        ├── TimeoutException           ← 异步操作等了太久（如Future.get()超时）
        └── ReflectiveOperationException（反射相关操作异常）
            ├── ClassNotFoundException ← Class.forName()显式按类名未找到类文件
            ├── NoSuchMethodException  ← getMethod()找不到对应方法
            ├── NoSuchFieldException   ← getField()找不到对应字段
            ├── IllegalAccessException ← 试图访问private等受保护成员（未setAccessible(true)）
            └── InvocationTargetException ← 反射调用的底层方法内部抛出异常
```
#### 如何处理异常
1）try-catch-finally
```java
try {
    // 可能抛异常的代码
} catch (IOException e) {
    // 处理特定异常
} catch (Exception e) {
    // 兜底处理
} finally {
    // 无论是否异常都会执行（资源清理）
    // 当在try或catch中遇到return语句时，finally中的语句将在方法返回之前被执行
}
// 注意：当try语句和finally语句中都有return语句时，try语句块中的return语句会被忽略。这是因为try语句中的return返回值会先被暂存在一个本地变量中，当执行到finally语句中的return之后，这个本地变量的值就变为了finally语句中的return返回值
```
2）throws / throw（向上抛出）
```java
// throws：声明方法可能抛出异常，让调用方负责处理
public void loadConfig() throws IOException {
    FileReader reader = new FileReader("config.txt");
}

// throw：主动抛出一个异常实例
public void setSpeed(int speed) {
    if (speed < 0) {
        throw new IllegalArgumentException("速度不能为负数：" + speed);
    }
}
```
3）try-with-resources

```java
// 自动关闭实现了AutoCloseable的资源
try (FileReader reader = new FileReader("file.txt")) {
    // 使用reader
} // 自动调用reader.close()
```
等同于下面使用 finally 的方式：

```java
FileReader reader = new FileReader("file.txt");
try {
    // 使用reader
} finally {
    if (reader != null) {
        try {
            reader.close();
        } catch (IOException closeException) {
            // close失败也要处理
        }
    }
}
```

#### 自定义异常

Java 自定义异常就是通过继承 Exception（Checked）或 RuntimeException（Unchecked）来创建自己的异常类，用于表达业务逻辑中特定的错误场景，让语义更清晰，并且可以携带业务数据（可以在异常中添加自定义字段，如错误码、业务参数），而且调用方以针对不同异常类型做不同的 catch 处理。

```java
public class BusinessException extends Exception {

    private final int errorCode;

    public BusinessException(int errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }

    public int getErrorCode() {
        return errorCode;
    }
}
```
使用时：

```java
public void setSpeed(int speed) throws BusinessException {
    if (speed < 0) {
        throw new BusinessException(1001, "速度不能为负值");
    }
}
```

当然也不是仅仅可以继承 Exception 或 RuntimeException。可以选最贴近语义的父类：

| 继承自                   | 类型      | 适用场景                                                     |
| ------------------------ | --------- | ------------------------------------------------------------ |
| Exception                | Checked   | 通用异常，预期内可能发生的异常，调用方必须处理               |
| RuntimeException         | Unchecked | 通用异常，不应该发生的异常，调用方不必处理（发生了说明代码有 bug） |
| IOException              | Checked   | 与 I/O 相关的异常                                            |
| IllegalArgumentException | Unchecked | 参数校验失败                                                 |
| IllegalStateException    | Unchecked | 对象状态不合法                                               |

实际项目中需要注意的是，不要继承 Error，它表示 JVM 层面的严重错误（如 OOM），不应该由应用程序抛出；不要继承 Throwable，它是整个异常体系的根，继承它会把 Error 也包进来。

#### finally 中的代码一定会执行吗？

绝大多数情况下会，包括 try 或 catch 中有 return 时，finally 也会在方法返回之前执行。但有三种情况不会执行：
+ `System.exit()`：程序直接终止，JVM 立即关闭，不再执行任何代码。
+ 线程被强制终止：如 `Thread.stop()`，线程被立即杀死。
+ JVM 崩溃 — 如 Error 导致 JVM 进程本身崩溃，来不及执行 finally。

#### 异常的性能开销

比如下面的例子，当 str = "123" 时，两种方式性能几乎一样，因为 try-catch 没触发异常，开销只是在进入 try 块时注册了一个异常处理器，非常轻量。

当 str = "abc" 时，try-catch 会创建异常对象，需要遍历整个调用栈，并且还会涉及到内存分配（new Exception + 内部数组存栈帧），耗时量级为微秒级；而 if 仅仅是字符的比较，不涉及内存分配，耗时量级在纳秒级。

所以不要用异常替代可以通过 if-else 判断解决的问题。

```java
// 错误的方式：用异常做控制流
try {
    int value = Integer.parseInt(str);
} catch (NumberFormatException e) {
    value = 0;
}

// 争取的方式：先判断
if (str != null && str.matches("\\d+")) {
    value = Integer.parseInt(str);
} else {
    value = 0;
}
```
